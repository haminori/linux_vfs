# VFS Shell Emulator

Эмулятор командной строки UNIX-подобной ОС (вариант задания №19).

Реализовано:

- **Этап 1 (REPL).** GUI на Tkinter, парсер аргументов в кавычках,
  команды-заглушки `ls` и `cd`, команда `exit`, сообщения об ошибках.
- **Этап 2 (конфигурация).** Параметры командной строки `--vfs` и
  `--script`, отладочный вывод параметров, стартовый скрипт с
  комментариями и сообщениями об ошибках.

Виртуальная файловая система и остальные команды появятся на
следующих этапах, поэтому `ls` и `cd` пока лишь выводят своё имя и
аргументы.

## Структура репозитория

```
src/vfs_shell/   исходный код эмулятора
tests/           модульные тесты (pytest)
scripts/
  emulator/      стартовые скрипты эмулятора (.txt)
  os/            скрипты ОС (.sh и .bat), запускающие эмулятор
vfs_samples/     пример файла для параметра --vfs
demo_logs/       транскрипты демонстрации работы
run.sh, run.bat  запуск эмулятора в Linux/macOS и в Windows
```

## Запуск

Нужен Python 3.10+ с модулем `tkinter` (в Windows он входит в
установку с python.org, компонент "tcl/tk and IDLE").

Linux/macOS:

```bash
./run.sh --vfs vfs_samples/demo.csv --script scripts/emulator/stage2_basic.txt
```

Windows (cmd):

```cmd
run.bat --vfs vfs_samples\demo.csv --script scripts\emulator\stage2_basic.txt
```

## Параметры командной строки

| Параметр          | Назначение                                 |
|-------------------|--------------------------------------------|
| `--vfs ПУТЬ`      | путь к физическому расположению VFS        |
| `--script ПУТЬ`   | путь к стартовому скрипту эмулятора        |

Оба параметра необязательны. Имя VFS для заголовка окна берётся из
последнего компонента пути `--vfs`; без параметра используется имя
`vfs (память)`. Неизвестный параметр приводит к сообщению об ошибке
и завершению с ненулевым кодом.

**Отладочный вывод.** При запуске все заданные параметры печатаются в
консоль и в верхней части окна эмулятора.

## Стартовый скрипт

Текстовый файл UTF-8, по одной команде эмулятора в строке.

- Комментарии используют синтаксис Python: `#` начинает комментарий
  до конца строки (в начале строки или после пробела). Символ `#`
  внутри кавычек комментарием не считается.
- Пустые строки и комментарии пропускаются.
- Во время выполнения в окне отображается и ввод (`$ команда`), и
  вывод, как в живом диалоге.
- При первой ошибке выполнение останавливается, а сообщение с номером
  строки показывается в окне и в консоли; после этого окно остаётся
  открытым для интерактивной работы.
- Команда `exit` в скрипте закрывает эмулятор.
- Если файл скрипта не найден или не читается, об этом сообщается
  так же, а эмулятор запускается без скрипта.

## Скрипты ОС для тестирования параметров

В `scripts/os/` лежат по три скрипта для Linux (`.sh`) и Windows
(`.bat`). Каждый запускает эмулятор без параметров, только с `--vfs`,
только с `--script` и с обоими параметрами:

- `stage2_basic` — корректный стартовый скрипт;
- `stage2_comments` — скрипт с комментариями и пустыми строками;
- `stage2_errors` — скрипты с ошибками (неизвестная команда, неверные
  аргументы), `exit`, несуществующий файл скрипта, неизвестный
  параметр командной строки.

Каждый запуск открывает окно; следующий запуск начнётся после его
закрытия.

## Демонстрация

В среде без дисплея окно открыть нельзя, поэтому модуль
`vfs_shell.demo` принимает те же параметры и печатает ровно те строки,
которые показало бы окно:

```bash
PYTHONPATH=src python3 -m vfs_shell.demo --script scripts/emulator/stage2_basic.txt
```

Готовые транскрипты: `demo_logs/stage1_demo.log` (интерактивный
диалог этапа 1) и `demo_logs/stage2.log` (все сценарии запуска этапа 2,
включая ошибки).
